# DMN-правила выбора тренировки

После расчёта Readiness Index система определяет тренировочную рекомендацию через набор бизнес-правил. DMN-слой отделяет логику от кода backend и упрощает изменение правил без деплоя.

## Decision Table

| Readiness Index | Training Type | Intensity | Duration (мин) | Уведомить тренера |
|---|---|---|---|---|
| < 4.0 | REST | NONE | 0 | ✅ Да |
| 4.0 – 5.9 | YOGA | LOW | 30 | — |
| 6.0 – 6.9 | CARDIO | MEDIUM | 40 | — |
| 7.0 – 7.9 | CARDIO | MEDIUM | 45 | — |
| 8.0 – 8.9 | STRENGTH | HIGH | 60 | — |
| 9.0 – 10.0 | STRENGTH | HIGH | 75 | — |

## Порог уведомления тренера

Если `readinessIndex < 4.0`, n8n публикует событие `notification.send` в Kafka, после чего тренер получает push-уведомление через OneSignal.

## Назначение DMN

DMN-правила хранятся отдельно от кода: их можно изменять в интерфейсе n8n без изменения бэкенда. Это делает систему гибкой для A/B-тестирования разных стратегий нагрузки.
