# API-документация

API-документация в проекте разделяется на два уровня: текстовое описание и OpenAPI-спецификация.

## Структура

| Уровень | Где хранится | Назначение |
|---|---|---|
| OpenAPI YAML | `api_specs/openapi.yaml` | Контракт: схемы, параметры, коды ответов |
| Markdown | `docs/04-api/*.md` | Контекст: бизнес-правила, примеры, объяснения |
| Redoc | `/api` (через redocusaurus) | Интерактивная документация для разработчиков |

## Общие правила

- OpenAPI-спеки хранятся в каталоге `api_specs/`.
- Интерактивная документация публикуется через **redocusaurus** по маршруту `/api`.
- Для каждой группы методов — отдельная Markdown-страница с назначением и бизнес-контекстом.

## Что должно быть описано для каждого метода

- Назначение метода (1–2 предложения)
- Входные параметры (path, query, body)
- Ответы (коды и структура)
- Ошибки (коды и описание)
- Бизнес-правила и ограничения доступа

## Принцип оформления

Redoc — источник **интерактивного контракта** (что принимает и возвращает API).  
Markdown-страницы — место для **пояснений и контекста** (зачем этот метод, кто его вызывает, что происходит после).

Эти два уровня дополняют друг друга и не дублируют.
