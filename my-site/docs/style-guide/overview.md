# Style Guide

Этот раздел описывает правила оформления документации в проекте FitAdapt. Единый стиль делает документацию предсказуемой: читатель знает, где искать информацию, а автор — как её оформлять.

## Главное правило

Документация пишется для читателя, а не для автора. Если абзац понятен только автору, его нужно переписать.

## Что входит в style guide

- [Структура документа](./structure) — front matter, заголовки, имена файлов
- [Диаграммы](./diagrams) — когда PlantUML, когда draw.io
- [API-документация](./api) — правила описания методов, Redoc, OpenAPI

## Зачем нужен style guide

Без общих договорённостей документация быстро становится непоследовательной: заголовки оформляются по-разному, front matter заполняется неравномерно, а диаграммы теряют контекст.

Style guide фиксирует единый подход и снижает стоимость дальнейшего сопровождения документации.

## Docs as Code

Документация в FitAdapt хранится в GitHub рядом с кодом и изменяется через pull requests. Каждая правка документации — это коммит. Это позволяет:

- отслеживать историю изменений
- делать ревью документации так же, как ревью кода
- автоматически деплоить при пуше в `main`
