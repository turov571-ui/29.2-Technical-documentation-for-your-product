# Интеграция с n8n

n8n используется как self-hosted workflow-движок для автоматизации расчётов и оркестрации событийных сценариев.

## Основные функции n8n в проекте

- Подписка на Kafka-топик `health.data.saved`
- Расчёт Readiness Index по четырём метрикам
- Применение DMN-правил выбора типа тренировки
- Запись результата в backend через `POST /recommendations`
- Публикация события `notification.send` при низком индексе
- HTTP-запрос в OneSignal API (через Notification Worker или напрямую)

## Причины выбора

Использование n8n позволяет менять бизнес-логику расчётов (веса метрик, DMN-правила, пороги уведомлений) без изменения и деплоя основного backend-кода. Это особенно важно на этапе проверки гипотез.

## Архитектурное решение

n8n — это инфраструктурный компонент «на периферии» системы. Он не хранит состояние клиентов и не является источником правды: вся персистентность остаётся в PostgreSQL через Backend API.
