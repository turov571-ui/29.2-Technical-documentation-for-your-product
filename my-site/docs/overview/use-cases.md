# Use Cases

## Сценарии клиента (роль CLIENT)

| ID | Название | Краткое описание |
|---|---|---|
| UC-01 | Ввод данных о здоровье | Клиент вносит ежедневные метрики: вес, энергия, сон, настроение |
| UC-02 | Просмотр рекомендации | Клиент получает рекомендацию по тренировке на сегодня |
| UC-03 | История метрик | Клиент видит динамику своих показателей за период |

## Сценарии тренера (роль TRAINER)

| ID | Название | Краткое описание |
|---|---|---|
| UC-04 | Просмотр списка клиентов | Тренер видит всех своих клиентов с текущими индексами |
| UC-05 | Карточка клиента | Тренер открывает детальную информацию по клиенту |
| UC-06 | Получение уведомления | Push-уведомление, если индекс клиента ниже порога |

## UC-01: Ввод данных о здоровье

**Актор:** Клиент  
**Предусловие:** Клиент авторизован

**Основной поток:**
1. Клиент открывает экран `/health`
2. Система загружает последний профиль (`GET /health-profile`) для предзаполнения
3. Клиент корректирует значения и нажимает «Отправить»
4. Система сохраняет данные (`POST /health-data`)
5. Система перенаправляет клиента на `/recommendation`

**Альтернативный поток 4а — сеть недоступна:**  
4а.1. Фронтенд повторяет запрос с тем же `X-Idempotency-Key`  
4а.2. Сервер возвращает `200 OK` если данные уже сохранены

## UC-04: Просмотр списка клиентов

**Актор:** Тренер  
**Предусловие:** Тренер авторизован, роль = TRAINER

**Основной поток:**
1. Тренер открывает экран `/trainer/clients`
2. Система загружает постраничный список (`GET /trainer/clients?page=0&size=20&sort=readinessIndex,desc`)
3. Тренер видит таблицу: имя, Readiness Index, тип рекомендации, дата записи
4. Тренер кликает строку → переход на `/trainer/clients/{clientId}`
