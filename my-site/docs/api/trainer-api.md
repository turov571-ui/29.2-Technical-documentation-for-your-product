# API тренера

Методы, используемые тренером для просмотра состояния клиентов. Доступны только пользователям с ролью **TRAINER**.

## `GET /trainer/clients`

**Назначение:** Постраничный список клиентов тренера с последними индексами и рекомендациями.

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `page` | int | 0 | Номер страницы (с 0) |
| `size` | int | 20 | Размер страницы (1–100) |
| `sort` | string | — | Поле и направление, напр. `readinessIndex,desc` |

**Ответы:** `200 OK` — объект `ClientListResponse` с массивом `content` и метаданными пагинации; `403 Forbidden` — не тренер.

## `GET /trainer/clients/\{clientId\}`

**Назначение:** Детальная карточка клиента: профиль, индекс, последняя рекомендация, история метрик.

**Path-параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `clientId` | uuid | Идентификатор клиента |

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `historyDays` | int | 30 | Глубина истории метрик в днях (1–365) |

**Пример запроса:**

```http
GET /trainer/clients/{clientId}?historyDays=30
Authorization: Bearer <jwt>
```

**Ответы:** `200 OK` — объект `ClientDetailResponse`; `404 Not Found` — клиент не найден.

## Бизнес-правила

- Тренер видит только клиентов, связанных с ним через `trainer_client`.
- История метрик `healthHistory` — массив записей `HealthHistoryRecord` за указанный период.
