# API метрик здоровья

Методы, используемые клиентом для передачи ежедневных показателей состояния здоровья.

## GET /health-profile

**Назначение:** Получить последний профиль здоровья для предзаполнения формы на экране `/health`.

**Роль:** CLIENT  
**Ответ:** `200 OK` — объект `HealthProfile`; `404` — профиль не найден (первый вход).

| Поле ответа | Тип | Описание |
|---|---|---|
| `clientId` | uuid | Идентификатор клиента |
| `weight` | float | Последний записанный вес |
| `energyLevel` | int | Уровень энергии (1–10) |
| `sleepQuality` | int | Качество сна (1–10) |
| `mood` | int | Настроение (1–10) |
| `recordedAt` | datetime | Дата последней записи |

## POST /health-data

**Назначение:** Сохранить новую запись метрик. Вызывается при нажатии «Отправить» на экране `/health`.

**Роль:** CLIENT  
**Заголовок:** `X-Idempotency-Key: <uuid>` — защита от дублей при повторных отправках.

| Поле запроса | Тип | Обязательно | Описание |
|---|---|---|---|
| `weight` | float | ✅ | Вес в кг (20–300) |
| `energyLevel` | int | ✅ | 1–10 |
| `sleepQuality` | int | ✅ | 1–10 |
| `mood` | int | ✅ | 1–10 |

**Ответы:**
- `201 Created` — данные сохранены
- `200 OK` — данные уже были сохранены (idempotency)
- `400 Bad Request` — невалидные данные
- `401 Unauthorized` — не авторизован

**Бизнес-правило:** после сохранения backend публикует событие `health.data.saved` в Kafka.
